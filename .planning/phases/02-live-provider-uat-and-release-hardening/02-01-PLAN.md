# Plan 02-01: Provider Live-Smoke Checks

**Phase:** 2 - Live Provider UAT And Release Hardening
**Status:** Complete
**Requirements:** DSK-15

## Goal

Run live smoke tests with real official DeepSeek V4 and SiliconFlow DeepSeek V3.2 credentials, or document exactly what remains unrun if credentials are unavailable.

## Tasks

1. Confirm the local app can select official DeepSeek V4 Flash/Pro or aliases with one DeepSeek family adapter.
2. Run official DeepSeek V4 with thinking disabled and verify request behavior uses `thinking.type=disabled`.
3. Run official DeepSeek V4 with `reasoning_effort=high` and verify the request succeeds without sampling controls.
4. Run official DeepSeek V4 with `reasoning_effort=max` and verify the request succeeds without sampling controls.
5. Run SiliconFlow DeepSeek V3.2 with existing thinking settings and verify `enable_thinking` / `thinking_budget` behavior remains compatible.
6. Confirm SiliconFlow V3.2 sampling controls remain user-configurable and are not stripped as if it were V4.
7. Perform a bounded context-window sanity check: verify V4 shows 1M metadata and V3.2 remains 128K metadata; avoid expensive 1M-token calls unless explicitly approved.
8. Record provider, model ID, thinking mode, expected request dialect, result, and any provider error in the phase summary.

## Must Haves

- Do not expose API keys in logs, docs, screenshots, or commits.
- Smoke prompts should be minimal and deterministic.
- Failure records must distinguish app bug, provider access issue, rate limit, and unavailable model.
- If SiliconFlow still has no V4 model, mark SiliconFlow V4 as future-compatible by contract tests only, not live-tested.

## Verification

- Official V4 disabled/high/max live smoke passes or is documented as blocked by provider/key access.
- SiliconFlow V3.2 live smoke passes or is documented as blocked by provider/key access.
- Phase summary captures exact model IDs and absolute test date.
