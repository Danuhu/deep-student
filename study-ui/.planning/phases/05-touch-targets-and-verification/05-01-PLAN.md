# Plan 01: Touch Targets And Verification

<objective>
Complete Phase 5 by making phone/tablet controls expose 44px touch targets through the full compact range, preserving desktop compact sizing, repairing stale tests, and producing automated plus manual acceptance evidence for the responsive migration.
</objective>

<threat_model>
## Threat Model

### T-01: Tablet Targets Shrink At `md`
- **Severity:** high
- **Risk:** `md:h-*`, `md:min-h-*`, and `md:size-*` classes start at 768px, which is still tablet/touch density for this project.
- **Mitigation:** Replace touch-target compaction with `lg:` or density-token behavior and add source tests rejecting the old `md:` height/min-height shrink classes.

### T-02: Desktop Density Gets Bloated
- **Severity:** medium
- **Risk:** Forcing every desktop control to 44px would regress the compact Tauri desktop shell.
- **Mitigation:** Use `--touch-target-size` for touch density and desktop-safe `lg:`/compact tokens so desktop can return to 32-40px controls.

### T-03: Switch Hit Area Breaks Semantics Or Focus
- **Severity:** medium
- **Risk:** Enlarging the switch visually or through wrappers can clip focus rings, overlap targets, or weaken Radix switch semantics.
- **Mitigation:** Keep `SwitchPrimitive.Root` and `SwitchPrimitive.Thumb`, test the 44px root/hit-area contract, and keep settings row labels connected to the switch id.

### T-04: Stale Tests Mask Verification Quality
- **Severity:** high
- **Risk:** Existing source tests still assert Phase 4 pre-change classes and can fail for the wrong reason.
- **Mitigation:** Repair stale assertions in `ShellButton.source.test.ts` and `SettingsPanel.test.ts`, then run the targeted suite before lint/build.

### T-05: Manual Acceptance Is Overclaimed
- **Severity:** high
- **Risk:** Automated source tests cannot prove real viewport, safe-area, keyboard, titlebar, and resize behavior.
- **Mitigation:** Create a committed manual acceptance artifact with exact viewport rows, expected observations, and PASS/FLAG/FAIL/N/A status vocabulary.
</threat_model>
