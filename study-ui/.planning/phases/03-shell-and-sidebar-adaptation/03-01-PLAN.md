# Plan 01: Shell And Sidebar Adaptation

<objective>
Complete Phase 3 by refining compact drawer behavior, reducing compact app topbar noise, and protecting desktop docked/titlebar/window behavior with source tests.
</objective>

<threat_model>
## Threat Model

### T-01: Compact Drawer Does Not Close After Navigation
- **Severity:** medium
- **Risk:** Phone/tablet users select a destination but remain trapped behind an open drawer.
- **Mitigation:** Add compact-only `closeOnSelect` and pass it only when `layoutPolicy.sidebarMode === "drawer"`.

### T-02: Drawer Closes On Disclosure Instead Of Navigation
- **Severity:** medium
- **Risk:** Folder expand/collapse becomes frustrating on compact widths.
- **Mitigation:** Do not wire `closeSidebarAfterSelection` to folder disclosure rows.

### T-03: Desktop Titlebar Regression
- **Severity:** high
- **Risk:** Mobile adaptation could accidentally remove macOS traffic-light alignment, Windows custom controls, or resize handles.
- **Mitigation:** Do not edit titlebar/window modules unless required. Add/keep source tests that assert AppChrome still renders those contracts.

### T-04: Compact Topbar Loses Core Actions
- **Severity:** medium
- **Risk:** Hiding all right-side actions could leave compact users without an obvious action beyond the drawer.
- **Mitigation:** Replace desktop status noise with one compact `新建对话` icon action.
</threat_model>
